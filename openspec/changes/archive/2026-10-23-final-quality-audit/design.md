# Design

## Context

State at the start (observed, not assumed): all earlier changes are merged into `main`; the toolchain has Ruff, Black, mypy and pre-commit but no security scanner and no dependency audit; there are no response-header or request-size protections and no CORS or trusted-host configuration (so cross-origin browser access is simply not allowed); the Dockerfile runs as root; Compose publishes PostgreSQL (5432), RabbitMQ (5672) and the RabbitMQ management UI (15672) on all interfaces; `.dockerignore` already excludes `.env`. A grep of production code for risky constructs found: `assert` used for type narrowing in `components/experiments/runner.py` and `admin/__init__.py`, `random.uniform` for retry jitter, the default `api_host = "0.0.0.0"`, a broad `except Exception` in the health check (intentional, returns `failing` without echoing errors), `urlopen` in `scripts/kan.py`, and a placeholder constant that looks like a password. No `eval`, `exec`, `pickle`, `subprocess`, unsafe YAML or string-built SQL in production code. See the proposal for motivation and the specs for behavior.

## Goals / Non-Goals

**Goals:**
- Every automated and manual check has a command, a result and a recorded outcome for each finding.
- Close the gaps scans normally report (headers, caching, body size, container user, exposed ports) without breaking docs or the admin panel.
- Prove, with tests, that hostile text is inert in every sink.

**Non-Goals:**
- New features beyond the hardening above (login rate limiting is a recorded follow-up), a WAF, TLS termination, secret manager (see proposal).

## Decisions

- **Static analysis: Bandit.** `bandit` 1.9.x (Apache-2.0; depends on PyYAML, stevedore and rich) as a dev dependency, configured under `[tool.bandit]` in `pyproject.toml`: scan `components`, `api`, `admin`, `cli.py`, `main.py`, `taskiq_app.py`, `migrations` and `scripts`; exclude `tests`, `.venv` and caches (asserts and subprocess helpers in tests are expected); report at medium severity and above (`-ll`). A local pre-commit hook mirrors the existing ones (`poetry run bandit -c pyproject.toml ...`). Suppressions must be `# nosec Bxxx - reason`; a small test greps production code and fails if a `# nosec` has no reason. Expected findings and decisions: replace the two production `assert` statements with explicit checks that raise a clear error (an `assert` disappears under `python -O`); keep `random.uniform` for retry jitter with `# nosec B311 - non-cryptographic jitter`; change the default `API_HOST` to `127.0.0.1` and set `API_HOST: 0.0.0.0` explicitly in the Compose `api` service (a container must listen on all interfaces; a bare `python main.py API` should not), documented as the only behavior change of the scan work; validate the scheme of the Kan base URL in `scripts/kan.py` (http or https) and suppress with reason; justify the placeholder constant. The exact list is whatever the scan reports; the register records each.
- **Dependency audit: pip-audit.** `pip-audit` as a dev dependency, run as `poetry run pip-audit` against the environment installed from `poetry.lock` (so it audits the locked versions, including transitive ones). Fix by upgrading within constraints (`poetry update <pkg>`) when a fixed version exists; otherwise record an accepted exception with reason and review date. Network access to the vulnerability database is required; if unavailable it is reported as not run, never as passed.
- **OWASP review and dynamic scan.** Static analysis cannot see configuration, authorization or business-logic flaws, so a table in `docs/security.md` maps the OWASP Top 10 (2021) and the API Security Top 10 (2023) to evidence in code and tests (for example broken object level authorization to `tests/core/test_isolation.py`; unrestricted resource consumption to pagination caps, field limits, the new body limit and bounded output; authentication failures to Argon2id, token rotation and the known rate-limit gap). OWASP ZAP runs in a container (`ghcr.io/zaproxy/zaproxy:stable`) as a baseline scan plus an OpenAPI-driven API scan (`zap-api-scan.py -f openapi`), authenticated with a throwaway user's access token passed as a request header, against the API started from the working tree on a spare port with a scratch database, throwaway secrets and the panel and docs enabled. Reports stay outside the repository; the alerts and outcomes go to the register. The developer's running stack is never targeted.
- **HTTP hardening.** One pure ASGI middleware in `api/middleware.py` (not `BaseHTTPMiddleware`, which interferes with streaming responses and background work) that: adds `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer` to every response including errors; adds `Strict-Transport-Security` only when `HSTS_MAX_AGE_SECONDS` is set above zero; sets `Cache-Control: no-store` for `/api/v1/auth/*` and for any request that carried an `Authorization` header or the admin session cookie; and enforces `MAX_REQUEST_BODY_BYTES` (default 2 MiB): reject early on a declared `Content-Length`, and for chunked bodies count bytes in a wrapped `receive` and answer 413 before the application reads more. The middleware also adds a `Content-Security-Policy`: `default-src 'none'; frame-ancestors 'none'` (plus `base-uri` and `form-action` `'none'`) for everything that is not an HTML document, and for the HTML pages `/docs*`, `/redoc*` and `/admin*` a page policy (CDN or `'self'` for scripts and styles) whose inline scripts are allowed by SHA-256 hash, computed from the served body (a small HTML response is buffered), so no `'unsafe-inline'` for scripts; `style-src` keeps `'unsafe-inline'` because Swagger UI and the panel set inline styles. The unfixed Swagger UI CDN SRI finding is accepted (docs can be switched off). The middleware wraps the whole app, so it also covers the mounted admin panel. Settings are optional with safe defaults.
- **Container hardening.** Dockerfile: create an unprivileged user (fixed uid), own `/app` for it, `USER` it before `CMD`. Compose: bind PostgreSQL, RabbitMQ and the RabbitMQ management UI to `127.0.0.1`, add `security_opt: no-new-privileges` for `api` and `worker`. The image is built and the container smoke-tested on a spare port against a scratch database without touching the running dev containers (the dev stack keeps running the old image until the user rebuilds).
- **Untrusted content.** The guarantee is about blast radius and data handling, because prompt injection into the model under test is the intended use of an evaluation platform. The code already avoids interpretation (single-pass literal substitution, no tool calling, deterministic evaluators, CSV neutralization, content-free logs). This change adds a test suite under `tests/security/` with a shared hostile corpus (template syntax, placeholder smuggling, instruction-override and exfiltration prompts, shell/SQL/Python/HTML/markdown payloads, `tool_call` JSON, formula prefixes, control characters, huge and deeply nested values) run against every sink: prompt rendering (purity checked by AST: no I/O or imports of repositories in the render helpers), the runner with a fake provider that returns hostile output, storage and API round-trip, JSON and CSV export, the admin panel JSON endpoints, logs and evaluators. A cross-tenant test shows hostile content naming another tenant's ids has no effect on what is read or written. Future LLM-as-a-judge features must reuse the corpus; this is noted in `docs/security.md`.
- **Bounded stored output.** A setting `MAX_STORED_RESPONSE_CHARS` (default 1,000,000) truncates the stored `response_text` with a visible marker and sets `experiment_results.response_truncated` (new boolean column, `NOT NULL DEFAULT false`, migration `0007`, exposed in the result schema and exports). Truncation happens in the runner when the outcome is built, before storage, and is logged without content. Existing rows keep `false`.
- **Code review and best practices.** The whole code base is reviewed read-only by independent reviewer agents in slices (core, auth, users, organizations and access; datasets, experiments and evaluation; metrics, exports and LLM providers; API, admin, CLI and tasks; tests, tooling, Docker and docs) against a checklist: the layering and conventions in CLAUDE.md, async correctness (no blocking work on the event loop, correct cancellation handling), error handling and messages, typing quality (`Any`, ignores), dead code and duplication, naming, comment and docstring value, configuration defaults, logging, and test quality. Findings are triaged: High and Medium are fixed in this change; Low ones become Kan cards. Stricter Ruff rule sets (for example `B`, `UP`, `SIM`, `ASYNC`, `PT`, `RUF`) are evaluated and enabled where they pass cleanly or with justified per-file ignores; flake8-bandit (`S`) is not added because Bandit itself is.
- **Findings register.** `docs/security.md` holds how to run each check, the OWASP table, the findings table (source, severity, location, outcome) and the accepted-risk list with owner and review date.

## Risks / Trade-offs

- [Scanner noise and false positives] -> triage, inline `nosec` with reason, enforced by a test; no blanket skips.
- [Security headers or body limits breaking Swagger UI or the admin panel] -> tests load both; the middleware only adds headers and limits sizes.
- [Chunked body limit implemented wrongly leaks memory or hangs] -> pure ASGI wrapper with explicit tests for declared length, chunked bodies and exact-limit boundaries.
- [Truncation changes stored data semantics] -> opt-out by setting a very large limit, explicit marker and flag, migration with a safe default.
- [ZAP needs container images and network access] -> reported as not run if unavailable; no fabricated results.
- [Changing the default `API_HOST` surprises someone running the API outside containers] -> documented in README and `.env.example`; Compose sets it explicitly.
- [Login rate limiting stays a known gap] -> explicit follow-up Kan card, stated in `docs/security.md`.

## Migration Plan

Revision `0007` adds the flag column with a default; downgrade drops it. Settings are optional. Rebuild the image to pick up the non-root user and set `API_HOST` through Compose (already in the file); `JWT_SECRET_KEY` must exist in `.env` as before.
